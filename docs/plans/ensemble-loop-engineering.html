01源文档在说什么，Ensemble 该接哪一层

源文档把 loop engineering 拆成三层，两个 CLI 通用：

architecture 
外环  脚本 / CI 反复调 CLI              ← 决定「什么时候重新开始」
  └ 内环  agent 的 act → observe 循环    ← 决定「一轮里怎么收敛」
      └ 状态  CLAUDE.md / AGENTS.md / 任务文件  ← 决定「跨轮怎么不失忆」

核心论断也成立，直接搬过来：没有 verifier 的循环只是在重复烧钱。

映射到 Ensemble 时，位置要换：

CLI 层CLI 原语Ensemble 该由谁做
外环 loop.sh · claude -p · codex exec 反复拉起 Core 拥有迭代。用户已经坐在多 agent 工作台里，不要再让他们写 bash。
内环 Claude Stop hook exit 2；Codex 靠 prompt 把验证写死 Ensemble Stop-gate：agent 要收工时跑 verifier，失败则回灌，三 runtime 同一套。
状态 TASKS.md / PROGRESS.md / AGENTS.md / CLAUDE.md Loop board 可视化同一份落盘文件；runtime 继续读文件，UI 不另造一份真相。
不要做的事

不要在 Ensemble 里再开一个「运行 Ralph 脚本」面板，把 claude -p 当子进程套一层。 那是 CLI 的工作方式。Ensemble 的差异化是：人看着循环发生、多 agent 并行、权限可拦、失败可点进去、token 可记账。 夜间无人值守只是同一套 Loop 对象把交互审批换成 allowlist，不是另一条产品。

02现状对照：已有 / 半有 / 没有

对照源文档每一项原语，看 0.0.52 实际代码，不是愿望清单。

CLI 能力Ensemble 现状断点
非交互入口 claude -p / codex exec 半有 聊天就是驱动入口，但「一轮结束自动开下一轮」没有。人必须再按一次回车。
--permission-mode acceptEdits 已有 Agent Settings 已有 acceptEdits / bypassPermissions。Claude 走 canUseTool；Codex 这条是空操作。
--allowedTools Bash(npm test:*) 没有 工具白名单是全局/agent 级，不能按「这一次 loop 只许跑验证命令」收窄。
--max-turns 刻意没有 run-plan 写明三 runtime 都不设回合帽，靠 liveness + maxRunDurationMs。Loop 需要单独的迭代帽，不要改全局。
Stop hook 强制续跑 被关掉 Claude adapter settingSources: []，项目 .claude/settings.json 的 Stop / PostToolUse / SessionStart 不会加载。这是身份污染修复的副作用，不能直接打开。
Codex sandbox_mode + approval_policy 半有 sandboxMode 已有；没有 on-failure 甜点（平时不打扰、失败才问）。
AGENTS.md / CLAUDE.md 已有 Ensemble 在 project root 注入这两份文件（Claude 因自定义 systemPrompt 失去 walk-up，由 core 补上；Codex 自己读 cwd）。
跨轮记忆 TASKS.md 文件能写，UI 看不见 agent 可以用 Write 维护清单，但聊天里没有 board，人要自己去翻文件。
每轮 git commit 快照 半有 有 GitBranchChip 和 git API，没有「迭代结束自动 commit / 失败 reset」。
并行 worktree 半有 Team + 多 pane + 各自 projectRoot 已经能并行；没有「一键给每个成员建 worktree」。
长验证（测试套件） 已有 jobs job_start / job_wait 正是 verifier 该走的通道。primer 已禁止把长测试丢进 background shell。
context rot 治理 已有 /compact 交给 native CLI；/clear /reset-runtime /restart。缺的是 Loop 策略：每轮新会话 + 状态落盘 vs resume。
多 agent 评审 已有 peer_send（continue / review / fork）是 CLI 没有的外环原语，应该当 verifier 的一种。
最大的产品缺口

用户在项目里配好了 Claude Stop hook，在 Ensemble 里完全不生效。 Codex 这边本来就没有 Stop hook。两边的「不过就不许停」今天都靠人盯着聊天窗口再发一句「测试还红，继续」。 这就是源文档说的内环，Ensemble 现在把人留在回路里。

03产品原则：编排，不模仿 CLI

做

  • Loop 是 core 对象，挂在 agent（或 team）上，不挂在某个 CLI 上。
  • Verifier 是机器可判定的完成条件：命令、job、文件标记、peer review。
  • Stop-gate 由 Ensemble 执行，再按 runtime 翻译成「回灌用户消息 / 阻止 CLI 停」。
  • 状态文件仍是 markdown，UI 只是同一份文件的视图。
  • 三 runtime 同一套对话框、同一套 slash、同一套 header chip。

不做

  • 不重新打开 settingSources 全量加载（会再次吞掉 MEMORY.md 身份）。
  • 不把全局 maxTurns 改回去——只给 Loop 加迭代帽。
  • 不为 Claude 和 Codex 各做一套 Loop UX。
  • 不在没有 verifier 时允许启动 Loop（开环直接拒）。
  • 不让 Loop 默认 bypassPermissions。无人值守是显式升级，不是默认。

04对象模型：Loop 是什么

一个 Loop 绑定一个 agent（或一个 team board），最少四个字段：

loop 
Loop {
  goal            人说的目标（也写入 PROMPT.md / 首轮 user 消息）
  verifier        command | job | file-marker | peer-review
  doneWhen        机器可判定：exit 0 / 文件含 "## DONE" / reviewer 给出 LGTM
  iterationPolicy {
    maxIterations     外环帽（默认 20）
    maxTurnsPerIter   内环帽（Claude 可下发 max-turns；其它 runtime 由 core 计 tool round）
    session           resume | fresh+disk     ← 防 context rot
    snapshot          git-commit | none
    onFail            continue | stop | reset-to-last-snapshot
  }
  permission      沿用 agent.permissionMode，但可附加 allowedVerifierCmds
}

Verifier 四种，对应源文档三个配方 + Ensemble 多出来的 peer：

类型判定适用
command短命令 exit 0（npm test -w pkg / tsc --noEmit）内环 Stop-gate
jobjob_wait 成功（完整测试套、安装包、e2e）长验证，禁止 Bash 后台
file-marker落盘文件出现 ## DONE / ALL_COMPLETE外环收工，Ralph 式
peer-review另一个 agent peer_send review 回 LGTM团队回路，CLI 没有
Stop-gate 怎么实现才对等

不要指望 Codex 长出 Claude 那种 hook。不要给 Claude 偷偷打开项目 hooks、让 Codex 用户没这能力。
Core 在「本轮 result / idle」时拦截：跑 verifier → 失败则构造一条系统回灌（失败摘要 tail 40 行，和源文档 Stop hook stderr 一样）→ 自动 sendMessage 开下一内环。 Claude 若项目里已有 .claude/hooks/verify.sh，解析并收编进 Loop.verifier，在 UI 里显示「来自项目 hook」，而不是把 SDK settingSources 打开。

05命令如何对接

沿用现有 slash 习惯（/model 无参出 picker、有参直切）。Loop 是一组新命令，旧命令当 Loop 的零件，不改语义。

命令作用和现有命令的关系
/loop 无参 → 打开 Loop 对话框；有参 → 把当前输入当 goal，用上次 verifier 或项目探测到的测试命令开环 新。类比 /model picker
/loop stop · /loop pause · /loop resume 停 / 挂起 / 继续外环。pause 允许当前内环跑完再停 新
/verify 立刻跑当前 verifier，不等人，不改代码。结果进 transcript + board 新。人用来抽查
/done-when <spec> 设置/改完成条件。例：/done-when cmd:npm test · /done-when file:TASKS.md##DONE 新。没 verifier 不能 /loop
/max-iter N 只改当前 Loop 的外环帽 新。不碰全局 maxTurns
/compact · /clear · /reset-runtime 照旧。Loop 的 session: fresh 策略在每轮外环自动走 reset-runtime，人不用手敲 已有，Loop 调用它们
/status 增补一段 loop=：iter、verifier last、session policy、snapshot hash 已有，扩展打印
/cost Loop 进行中，统计页能按 loopId 过滤 已有，加 filter

自然语言也不要丢掉。用户说「把测试修到全绿」时，输入框上方出一条可撤销的 Loop 建议条，不是偷偷开环：

suggest 
检测到收敛任务。Verifier 候选：`npm test`（来自 package.json）
[ 用 /loop 开始 ]   [ 只用这一轮 ]   [ 忽略 ]

技能侧：三个源文档配方做成 SKILL.md（loop-tdd / loop-ralph / loop-pr-gate），Loop 对话框「配方」下拉直接套。强制 skill 挂到该 agent，避免每轮重新描述规则。

06循环怎么搭：交互流

6.1 开环 人在场

  1. 用户在某个 agent 的聊天里敲 /loop，或点 header 的 LOOP，或点建议条。
  2. 对话框预填：projectRoot 下探测到的测试命令；若存在 TASKS.md / .claude/hooks/verify.sh / AGENTS.md 完成条件，标「来自项目」。
  3. 用户确认 verifier、maxIterations、session 策略、是否每轮 git snapshot。没有 verifier 时「开始」按钮不可用。
  4. 若当前 permissionMode === default，对话框要求至少升到 acceptEdits（编辑自动放行，shell 仍问），并列出 verifier 命令将加入本 Loop 的 allowlist——等价 CLI 的 --allowedTools Bash(npm test:*)。
  5. 确认后：写/更新 TASKS.md（若选了 file-marker）、把 goal 作为第一轮 user 消息发出，header 出现 LOOP chip，右侧滑出 Loop board。
/loop · android开发
修到 monkey-android 单测全绿，每次只修一个失败测试
job · ./gradlew test
job exit 0
fresh + disk 防 context rot
20 · snapshot git commit
default → acceptEdits · allow ./gradlew test*
esc enter 开始

6.2 内环：不过就不许停 核心

  1. Agent 照常跑：Edit / 短 Bash / job_start。UI 不变，ToolCard 照旧。
  2. Agent 产出 result、状态回到 idle —— 这是 Stop-gate 的触发点，对标 Claude Stop hook。
  3. Core 跑 verifier（短命令直接跑；长任务必须 job）。
  4. 失败：transcript 插入一条系统块「VERIFY FAIL · iter 3」，摘要 tail，然后自动发送下一轮，用户不用打字。Chip 变橙。
  5. 成功且满足 doneWhen：Loop 收工，chip 变绿，board 锁住，给一段摘要（iter、cost、snapshot）。
  6. 成功但 file-marker 未 DONE：这是外环，开下一 iteration（见下）。

防无限循环（源文档 hook 里的 stop_hook_active）：同一 verifier 连续失败 N 次（默认 3）且 diff 为空 → pause，问人。不要静默烧钱。

6.3 外环：何时重新开始 context rot

两种 session 策略，对话框里二选一，默认推荐 fresh：

resume（保持 CLI session）

对标 --resume。适合短环、上下文还小。Ensemble 已有 lastSessionId。风险：源文档说的 context rot；DeepSeek 长思考会话会越来越慢。

fresh + disk（每轮新会话）

对标 Ralph。每轮外环：/reset-runtime 丢掉 resume，保留 Message 历史给 UI，状态只认 TASKS.md / board。下一轮 systemPrompt 只注入「未完成项 + 最近一次 verifier 失败」。这是长环的正确默认。

6.4 快照与回退

源文档：「不能回退的循环是负债」。Ensemble 有 git API，外环尾部：

  • snapshot: git-commit → 每轮 git add -A && git commit -m "loop(<agent>): iter N"，hash 写上 board。
  • verifier 比上一轮更差且用户选了 onFail: reset-to-last-snapshot → git reset --hard 到上一 hash，pause 告诉人。
  • 无 git 仓库 → 对话框里 snapshot 选项禁用，并写明「没有回退网」。

6.5 人怎么插手

  • 随时打字：插入一条 user 消息，当前内环不杀，下一次 Stop-gate 之后才喂进去（避免和自动回灌打架）。急的话点 header Stop，再说话。
  • 点 chip → pause / stop / 改 verifier。
  • 权限弹窗照旧。Loop allowlist 里的 verifier 命令不弹；其它 Bash 仍弹。这就是 acceptEdits + 收窄 allowedTools。
  • Codex：Loop 进行中把 sandbox 提到 workspace-write；网络默认关，verifier 需要装依赖再开。对标 approval_policy = on-failure 的甜点：失败才打扰。

6.6 团队并行环

源文档用 git worktree 并行。Ensemble 用 team：

  • Team 上可以开 一个 board、多个 runner。每个 runner agent 一个 worktree（调用已有 git，git worktree add），projectRoot 指过去。
  • 可选一个 reviewer agent，verifier 类型 peer-review。Runner 宣称 DONE 时 peer_send review，reviewer LGTM 才算外环完成。
  • 不要默认让 runner 互相 peer_send continue——那会把回路搅成聊天。并行环默认隔离，只有 board 和 reviewer 是共享面。

7.5 不要做成的界面

  • 不要独立「Loop IDE」大屏。Ensemble 的空间已经给多 agent 分屏了，Loop 是某个 pane 的状态。
  • 不要把 verifier 日志另开终端。失败摘要进 transcript（可折叠），完整日志走已有 job log 路径，点开即是。
  • 不要用进度条假装百分比。迭代是离散的，3/20 比 15% 诚实。

08三 runtime 对等

CLAUDE.md §3.7：少一条就是 silent fallback。Loop 必须三条都能跑，闸门语义可以不同，UX 不能缺。

Claude CLIOpenAI in-processCodex CLI
谁跑内环 现有 ClaudeAgentRuntime 现有 OpenAIAgentRuntime 现有 CodexCliRuntime
Stop-gate core 在 result 后跑 verifier；可选把项目 verify.sh 收编为 Loop.verifier，不打开 settingSources 同样：result 后 core 跑，回灌成下一条 user 同样。Codex 没有 hook，全靠这一层才有「不许停」
权限 acceptEdits + canUseTool；verifier 命令跳过弹窗 needsApproval 同样跳过 verifier sandbox workspace-write；Loop 期间等效 on-failure（失败才问）
内环帽 该 Loop 下发 SDK maxTurns（仅此 Loop，不改全局 null） core 计 tool round，到帽就 Stop-gate 无 per-call 审批，靠 sandbox + 外环帽 + duration
记忆 已注入 AGENTS.md/CLAUDE.md；Loop 再注入 TASKS.md 未完成段 同左（本来就靠 Ensemble 注入） Codex 自己读 cwd；Ensemble 保证 TASKS.md 在 root，不重复塞一份走样的
长验证 jobs MCP NormalizedTool jobs mcp-bridge jobs
fresh 轮 清 lastSessionId 再 query 新 in-process 会话 清 resume，新 exec
闸门不要装成一样

Claude 用户看见的仍是权限弹窗；Codex 用户看见的仍是 sandbox。Loop 只在 verifier 这条窄路上统一「失败就续跑」。 把 Codex 伪装成 canUseTool 会违反已锁定的安全模型。

09三个配方在 Ensemble 里长什么样

A · 测试驱动收敛

源文档：claude -p ... --max-turns 60 + Stop hook。

Ensemble：单 agent，/loop，verifier=command 或 job，session=resume（短）或 fresh（长），maxIterations=20，permission bump 到 acceptEdits。人盯着同一个 pane 看 FAIL 块自动续。

B · 夜间 Ralph

源文档：while :; do claude -p ...; git commit; grep ALL_COMPLETE

Ensemble：同一 Loop，session=fresh+disk，snapshot=on，doneWhen=file-marker，permission 显式升到 bypass 或 Codex danger-full-access（对话框二次确认）。托盘继续跑，早上 chip 绿或 pause 在连续失败。Usage 按 loopId 一栏。

C · PR 守门

源文档：codex exec "修 diff" --full-auto --json。

Ensemble：绑定当前 GitBranchChip 的分支。verifier=job（lint+typecheck+test）。可选第二个 agent 做 peer-review。Loop 结束条件 = job 绿 且 reviewer LGTM。这是 Ensemble 比 CLI 强的地方：评审不是 grep JSON，是另一个 pane 里可见的对话。

10分期

P0 · 内环先通
Loop 对象 + /loop 对话框 + Stop-gate（三 runtime）+ command/job verifier + 失败自动续 + header chip。没有 board 也能用，transcript 里的 VERIFY 块就够。
P1 · 外环可过夜
session fresh+disk、git snapshot、file-marker doneWhen、/status 增补、连续失败 pause、permission allowlist。
P2 · 团队回路
右侧 board 读写 TASKS.md、peer-review verifier、worktree 一键、三份 SKILL 配方、从项目 Stop hook / AGENTS.md 探测预填。
验收（P0 就该能感到的差别）

同一个 android开发 agent，点 /loop，verifier 填 ./gradlew test。 人不再每轮回车。测试红 → 系统块出现 → 模型自己继续改。测试绿 → chip 变绿 → 停。 Claude、DeepSeek-via-Claude、Codex 三条路同一套 chip，不能只有 Claude 会续跑。

源文档最后三个坑（无 verifier、context rot、不能回退）正好是 P0/P1 的三个门闩： 无 verifier 开不了环；长环默认 fresh+disk；有 git 才允许 snapshot 模式。 Ensemble 要把这三个门闩做成人在 UI 里能看见、能改、能停的东西，而不是 README 里的忠告。

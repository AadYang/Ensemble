# 在 Ensemble 里组建一个 AI 团队

这份说明面向「会用电脑、不一定写代码」的同事。看完你能自己建出一个能互相派活的 AI 小组。下面用正在用的 **JumpoAI项目组** 当完整例子，团队目的和每位成员的角色说明都可以直接复制。

---

## 先想清楚三件事

把 Ensemble 里的团队，想成办公室里的一个项目组：

1. **这个组要达成什么**（团队目的）  
   一句话写清项目是什么、给谁用、大家必须遵守的规矩。这句话会自动出现在每位成员的工作说明里。
2. **组里有谁**（角色名）  
   例如经理、工程师、观察员。名字就是他们互相喊人的方式，尽量短、好认、不要重名。
3. **每个人具体干什么、不能干什么**（角色说明）  
   写进「角色 / system prompt」。写得越清楚，他们越少跑偏、越少互相抢活。

你平时只要跟 **经理** 说话。经理拆任务、派给工程师；工程师做完再回报经理。你不用在几个窗口之间复制粘贴。

---

## 开始前准备

1. 打开 Ensemble，确认左下角或顶部显示已经连上（能点按钮）。
2. 至少已经加好一个「供应商」（Providers 里的 Claude / DeepSeek / Codex 等），并且能选出模型。没有供应商时，创建窗口里选不出模型。
3. 如果某个成员要改某个代码仓库，先在电脑上确认那个文件夹存在。创建时要填**完整路径**，例如 `D:\WorkSpace\AI-Camera-claw`。经理、观察员这种不写代码的角色，路径可以留空。

---

## 创建步骤

### 1. 打开新建窗口

窗口左侧是助手列表。点列表上方的 **「+ 团队」**（英文界面是 **「+ team」**）。

### 2. 填写团队

| 栏位 | 填什么 |
|---|---|
| **团队名** | 列表里显示的组名。例：`JumpoAI项目组` |
| **团队目的** | 这个组为什么存在、做什么、有哪些硬规矩。可多行。 |

团队目的不是给自己看的备注，而是每位成员都会读到的「全组任务书」。建议写：项目是什么、给谁用、代码大概在哪、测试和发版规矩、谁有权做最终决定。

### 3. 添加成员

默认会给你两名空成员。不够就点 **「加成员」**；多了点该行右边的 **×**。

每一位都要填：

| 栏位 | 填什么 |
|---|---|
| **角色名** | 列表里的名字，同事之间也用这个名字喊人。例：`Jumpo经理`、`Jumpo工程师` |
| **供应商 + 模型** | 这位用哪家 AI、哪个型号。同一组里可以混用，例如经理用 Codex，工程师用 DeepSeek。 |
| **项目文件夹** | 这位日常改哪个仓库。经理、观察员常留空。 |
| **角色说明** | 职责、禁止事项、有事找谁。这是最重要的一栏。 |

角色说明建议固定写成四段（Jumpo 组就是这个结构）：

- 你负责哪一块
- 你擅长做什么
- 需要拍板时找谁（通常是经理）
- 明确禁止的事（例如：工程师不许写 GitHub issue、不许自己 push、不许绕过经理去找别人）

### 4. 点「创建团队」

左侧会出现一个可折叠的团队标题，成员挂在下面。点某个名字，就可以在中间窗口跟他说话。

---

## 建好之后怎么用

1. **先点经理，把目标发给经理。** 例如：「按本周计划，把相机启动流程里的某某问题修掉。」
2. 经理会拆任务，并**主动交给**对应工程师。你不必自己去每个工程师窗口复述一遍。
3. 工程师做完会回报经理；需要你拍板时，经理会来问你。
4. 以后加人：把鼠标放到团队名上，点 **「+」**。
5. 改组名或团队目的：把鼠标放到团队名上，点 **「✎」**。改完后，成员下次开口会按新目的工作。
6. 改某一个人的角色说明：点他右边的设置（齿轮），改「角色 / system prompt」。

删掉团队**不会**删掉这些人，他们只是变成未编组。真要去掉某个人，需要单独删除那个助手。

开发面向美国儿童的 AI 相机：系统级权限的 launcher 应用，以及配套的服务端、网页端；支持多语言、多时区。主仓库在 `D:\WorkSpace\AI-Camera-claw`，另外还有语音后端、鉴权代理、家长端 App / 网站等配套项目。

## 这组为什么这样分工

- **一个经理对外**：你只喂目标，避免五六个工程师同时问你同一件事。
- **一个工程师一个仓库**：路径写在角色说明和项目文件夹里，减少改错项目。
- **写 issue 只给经理**：工程师可以读进展，但不能把 issue 记成流水账。
- **请示链条写死**：普通工程师找 Jumpo经理；家长端 App 找家长端经理。
- **独立观察故意孤立**：需要旁观、对照时用，不会掺进派活。

如果你要建别的组（文档组、调研组），流程完全一样，只换团队目的和角色说明。

## 常见问题

**只建了一个人，算团队吗？**  
算。但真正发挥「互相派活」至少要经理 + 一位做事的人。

**成员之间会自动看到对方窗口吗？**  
不会。他们只有在「交给同事」时，对方才会动。所以经理的角色说明里必须写清：拆完任务要派出去，不能只在自己窗口里空喊名字。

**AI 改文件、跑命令会不会直接执行？**  
默认会先问你。信任就允许；不放心就拒绝。Codex 成员还有只读 / 可写当前项目 / 完全放开三档，可在该成员设置里改。

**建错了怎么办？**  
改团队目的或角色说明即可，不必拆组重建。只有角色名、仓库、供应商选错，才需要改设置或删掉重加。

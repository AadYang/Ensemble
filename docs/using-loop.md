# Ensemble Loop 简要操作手册

这份说明面向「会用电脑、不一定写代码」的同事。看完你能自己开一轮 **带审阅的 Loop**：开发一直干到目标完成，审阅点头后才结束。

高级选项（命令校验、配方、worktree、每轮 git 提交等）这里不讲。日常开 Loop 用不到。

---

## Loop 是干什么的

平时你跟某个成员说一句话，他说完就停。Loop 是让他**停了还会自动接着干**，直到目标真的做完。

有审阅时，流程是：

1. 开发做事，把进度写进项目里的 `TASKS.md`
2. 开发认为全部做完，会在 `TASKS.md` 里写 `## DONE`
3. Ensemble 打开这块 LOOP 的**审阅黑板**（`REVIEW.md`），请审阅往上记意见
4. 开发在对应条目下回复并改代码；审阅结案。全部结案且审阅点头 → 整轮结束

你不用在几个窗口之间复制粘贴。

---

## 开始前准备

1. 已经有一个团队，里面至少 **一名开发 + 一名审阅**。两人组最合适。组很大（很多人、很多仓库）时，不要拿整组开 Loop——勾上「团队 Loop」后，**除审阅以外的所有成员都会同时领同一份目标**。
2. 开发已经绑好项目文件夹；审阅可以不绑仓库，但角色说明里应写清：只读、只评、不改代码。
3. 从**开发**的聊天窗口开 Loop，不要从审阅自己的窗口开（下拉里不能选自己当审阅）。

---

## 操作步骤

### 1. 打开对话框

点开要干活的那位开发。任选一种：

- 聊天框输入 `/loop` 回车
- 或点窗口上方的 **LOOP** 按钮

### 2. 填写目标

「目标」框写：**做完时什么必须为真**。写具体、可检查，不要写「尽量做好」。

系统会自己让他维护 `TASKS.md`、整件做完再写 `## DONE`。你不用在目标里教这些。

### 3. 其它栏位怎么留

| 栏位 | 怎么填 |
|---|---|
| **最大轮数** | 默认 `50` 即可。每停下一次算一轮。 |
| **权限提升** | 保持默认「循环期间自动接受编辑」。夜里没人点「允许」，文件改不动。 |
| **高级** | **不要展开。** |

### 4. 选出审阅；团队 Loop 按需勾

对话框下半部分（只有当前人属于某个团队时才会出现）：

1. **评审 agent** 下拉里选出审阅那个人，**不要留「（无）」**。选出之后，开发写完 `## DONE` 会打开审阅黑板，LOOP **停在评审中**，直到黑板上没有未结项且审阅点了通过。黑板 **30 分钟没有任何进展** 才会暂停。
2. **「作为团队 Loop 跑在 〈团队名〉」** 按情况勾：
   - **不勾（常见）**：只有当前这个开发在跑。选了审阅仍会送审并等待。
   - **勾上**：组里除审阅外的**所有人**都会领同一份目标；同样要等审阅回复。

两人组（开发 + 审阅）才适合勾团队 Loop。组很大时不要勾，否则不相干的成员也会同时开跑。

点 **开始**。

---

## 开跑之后看哪里

- 开发窗口上方会出现 `LOOP` 和轮数，例如 `iter 3/50`。
- 右侧会列出 `TASKS.md` 里的勾选清单（一开始可能是空的，开发会自己写）。
- 侧栏团队名旁边可能出现「执行中 / 评审中」。
- 开发认为做完、`TASKS.md` 出现 `## DONE` 时，会打开审阅黑板。窗口显示「评审中」。右侧除了任务清单，还会列出审阅条目和其下的回复。系统**不会**再往聊天里塞「去看黑板」，也不会用 `peer_send` 来回传审阅。双方下一轮自己就会用黑板（内置说明已经写好）。黑板 30 分钟无进展会暂停，不会假装过审。

**暂停 / 继续 / 停止**：用窗口上的按钮，或输入 `/loop pause`、`/loop resume`、`/loop stop`。停止不会删项目文件，只是不再自动下一轮。

连续几轮没有任何进展，系统会自己暂停，避免空转。到了最大轮数也会暂停。

---

## 审阅怎么回话

审阅**不用**再开一个 Loop，也**不要**用 `peer_send` 跟开发来回聊。开发送审后，在审阅自己的窗口里正常继续即可——他已经知道写在**审阅黑板**上：

| 意思 | 怎么做 |
|---|---|
| 记下一条要改的 | 往黑板 `post` 一条意见 |
| 针对某一条继续说 | 在那一条下面 `reply` |
| 这一条可以过了 | `resolve` 结案 |
| 全部没问题，整轮结束 | 没有未结项时 `lgtm` |

开发则在对应条目下回复改了什么，不要另开聊天频道。审阅只评对不对、有没有漏，不要自己改代码。

## 目标提示词示例

下面可以直接粘贴到「目标」框，按项目改路径和完成标准。

**修一个具体问题**

```
把相机冷启动偶发黑屏修掉。
完成标准：连续冷启动 10 次不再黑屏；改动只限启动流程相关文件；不扩功能、不加新设置项。
方案和代码必须经审阅通过后才算完成。未过审不得声称做完。
```

**做一个小功能**

```
给家长端 App 登录页增加「忘记密码」入口，走现有重置流程。
完成标准：Android 与 iOS 都能从登录页进入并走完重置；不改其它页面；不提交应用商店发版。
方案先过审阅再写代码；代码再过审阅。不要顺手重构。
```

**按已拍板的方案落地**

```
按仓库里已经拍板的方案，完成「启动流程超时提示」这一项。
完成标准：方案文件里列出的行为全部实现；TASKS.md 里每一项都勾掉；没有方案之外的改动。
每做完一块先过审阅，审阅通过后再做下一块。禁止在方案未确认时推进。
```

**文档 / 清单类（仍要审阅）**

```
把本周已拍板、已合并的改动整理进仓库根目录的 TASKS.md：正在做、做到哪、下一步。
完成标准：和当前代码一致；没有流水账；审阅确认没有漏项或写反。
只改这一份文件，不改业务代码。
```

写目标时记住三句：

1. **完成时什么必须为真**（可检查，不要「尽量」「优化一下」）
2. **不许做什么**（不扩功能、不发版、不改其它仓库）
3. **必须经审阅通过才算完**

## 常见问题

**下拉里看不到审阅？**  
当前窗口的人不是团队成员，或团队里只有他一个人。到开发的窗口再开 `/loop`。下拉里不会出现他自己。

**不勾团队 Loop，选了审阅还会等吗？**  
会。只要下拉里选了审阅，`## DONE` 之后 LOOP 就会送审并等待，不勾团队 Loop 也一样。团队勾选只决定「是一个人跑还是组里除审阅外都跑」。

**勾了团队 Loop 之后好几个窗口同时在动？**  
正常。除审阅外，组里每个人都会领同一份目标。组太大就不要整组开，先用「一名开发 + 一名审阅」的小组。

**审阅说了「可以」但 Loop 没结束？**  
要通过，审阅必须在黑板上 `lgtm`，并且没有未结的意见。只在聊天里说「可以」不会结束。

**开发一直不停、右侧清单是空的？**  
Loop 只认 `TASKS.md` 里的 `- [ ]` / `- [x]` 勾选。他如果只在聊天里报进度，系统看不见。让他按系统提示维护那份清单，或暂停后把目标写得更短、更单一。

**我想中途改目标？**  
先停止当前 Loop，再开一轮、贴新目标。不要在跑着的窗口里另说一件大事，两套目标会缠在一起。
